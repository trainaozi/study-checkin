1 云同步是什么？怎么工作的？

一句话概括：把你的打卡数据加密备份到你自己的 GitHub 私有 Gist 里，换设备后输入同样的令牌就能自动拉取合并。

工作原理

你的打卡数据平时存在浏览器本地（localStorage）。开启云同步后：

  • 数据会被上传到你 GitHub 账号下的一个私有 Gist（只有你自己能看）
  • 你的 GitHub 令牌会用你设置的同步口令加密后存在本地，不会明文落地
  • 换设备时，输入同一个 GitHub 令牌 + 同一个口令，就会自动找到同一份备份并合并
  • 每次同步都会自动合并本地与云端的数据（按时间戳取较新版本），不会互相覆盖

关键点：电脑和手机用「同一个 GitHub 令牌」连接即可自动同步，不需要手动抄 Gist ID。程序会自动在你账号下找到已有的备份并复用。

2 创建 GitHub 访问令牌（Token）

云同步只需要一个带 gist 权限的令牌，创建一次，双端通用。

1

打开 github.com/settings/tokens（需先登录 GitHub）

2

点击 Generate new token (classic)

3

Note 填 study-checkin（随便写，自己认得就行）

Expiration 建议选 No expiration（永不过期）或 1 year

4

只勾选 gist 这一项（在权限列表里找到 gist，勾上前面的方框）

不要勾其他权限，越少越安全。

5

拉到底点 Generate token，复制 ghp_ 开头的那串字符

这串令牌就是你的"钥匙"，电脑和手机都用同一把。 复制好之后保管好，GitHub 关闭页面后就看不到了（但可以随时重新生成）。

3 第一台设备（如电脑）首次连接

电脑 手机 操作完全一样，以下以电脑为例。

1

打开 学习打卡网站

2

进入「历史记录」页面（左侧导航或底部 Tab 的最后一个）

3

页面往下拉，找到「云同步 · 跨设备备份」卡片，点击「打开云同步」

4

在弹出的窗口中填写：

  • GitHub 访问令牌：粘贴刚才复制的 ghp_xxx
  • 同步口令：自己设一个口令（至少 6 位），用于加密令牌。记住它，遗忘了无法恢复
  • 确认口令：再输一遍
  • 已有备份 Gist ID：留空（留空会自动在你账号下创建/复用备份）
  • 自动同步：保持开启（推荐）
5

点「保存并连接」，等待几秒。看到右上角出现 ☁ 已同步 的绿色提示就成功了。

此时你的打卡数据已上传到云端。右上角的同步状态 pill 会持续显示同步状态。

4 第二台设备（如手机）连接同步

手机 电脑 第二台设备用同一个令牌 + 同一个口令连接即可。

1

在手机浏览器打开同一个网站链接

2

进入「历史记录」 → 找到「云同步」卡片 → 点「打开云同步」

3

填写完全相同的信息：

  • GitHub 访问令牌：和第一台同一个 ghp_xxx
  • 同步口令：和第一台同一个口令
  • 确认口令：再输一遍
  • 已有备份 Gist ID：留空（会自动找到第一台创建的备份）
4

点「保存并连接」，程序会自动发现你账号下已有的备份，拉取数据并合并到本机。

连接成功后，手机上的数据就和电脑同步了。之后任一端新增打卡，另一端点「立即同步」或等自动同步即可更新。

为什么之前双端不同步？

旧版本在「Gist ID 留空」时会为每台设备各新建一个独立的 Gist，导致电脑写自己的、手机写自己的，永不相遇。新版本已修复：留空时会自动在你账号下查找已有备份并复用，多台设备指向同一份数据。

如果你之前已经连过了，需要先断开再重新连接（见第 6 节），新逻辑才会生效。

5 日常使用

自动同步（推荐）

开启自动同步后，每次你新增计划、完成打卡、修改数据，程序会在 2.5 秒后自动上传到云端。右上角 pill 会短暂显示 同步中…，完成后变回 已同步。

你不需要做任何操作，正常用就行。

手动同步

如果想立刻拉取另一台设备的最新数据：

  • 点击右上角同步状态 pill，或进入「历史记录 → 云同步」卡片
  • 点「立即同步」按钮
  • 程序会先拉取云端最新数据合并到本地，再把合并结果上传

解锁

关闭页面后再打开，令牌会处于加密锁定状态（右上角显示 🔒 已加密）。需要输入同步口令解锁后才能同步。

解锁后会自动拉取一次云端数据并合并。

6 管理

点击右上角同步 pill 或「云同步」卡片的「打开」按钮，进入管理面板。

操作说明
立即同步手动触发一次 上传 + 拉取合并
自动同步 开关开关本地改动是否自动上传
更改口令用新口令重新加密本地令牌（云端数据不变）
锁定清除当前会话的令牌，需重新输入口令才能同步
断开并清除清除本机保存的加密令牌（云端 Gist 不删除，数据仍在）
复制 Gist ID复制完整备份 ID，用于手动指定备份（一般不需要）

如果你之前遇到了双端不同步的问题，修复后的正确操作是：

  1. 在两台设备上都进入云同步管理面板，点「断开并清除」
  2. 在第一台设备重新连接（令牌 + 口令，Gist ID 留空）
  3. 在第二台设备重新连接（同样的令牌 + 口令，Gist ID 留空）
  4. 程序会自动找到同一个备份，数据合并后双端同步

7 常见问题排查

Q：连接时提示「GitHub 令牌无效或权限不足」
A：检查令牌是否：
① 以 ghp_ 或 github_pat_ 开头，复制完整无多余空格；
② 勾选了 gist 权限；
③ 没有过期（在 token 页面看 Expiration 列）。
Q：解锁时提示「口令错误」
A：同步口令是你连接时自己设的，和 GitHub 密码无关。如果真忘了，只能点「断开并清除」后重新连接（会创建新备份，旧数据仍在云端 Gist 里）。
Q：两台设备都连上了，但数据还是不同步
A：确认两点：
① 两台设备用的是同一个 GitHub 令牌（不是各建各的）；
② 网站已更新到修复后的版本——进入「云同步」连接弹窗，看「已有备份 Gist ID」下面的提示是否写了「自动复用账号下的备份」。如果是旧的提示文字，说明网站还没更新，需要清除浏览器缓存或等 GitHub Pages 刷新。
③ 如果之前各连过一次，需要双端都先断开再重连（见第 6 节）。
Q：手机上输入令牌很不方便，能跳过吗？
A：令牌只需要输入一次（加密后存本地）。之后每次只需输入口令解锁即可。建议把令牌存在密码管理器里，或写入备忘录。
Q：自动同步会不会很费流量？
A：每次同步只传一个小 JSON（通常几 KB），且只在数据变化后 2.5 秒触发一次。日常使用几乎无感。
Q：换浏览器或清缓存后数据丢了怎么办？
A：只要之前开过云同步，重新打开网站 → 连接云同步（同一令牌 + 口令）→ 自动拉取合并即可恢复。
Q：安全吗？令牌会不会泄露？
A：令牌用 Web Crypto（AES-GCM + PBKDF2 20 万次迭代）加密后存在浏览器本地，不经过任何服务器传输。同步口令只在当前页面会话内存中，关闭即消失。云端 Gist 是私有的，只有你的令牌能访问。
